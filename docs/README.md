# Docs: start here

For contributors and agents. The repo's front page, with screenshots and a
quick start, is the [top-level README](../README.md).

**The pitch.** A small Python renderer in docker composes an 800×480 poster
(a Wikimedia Commons landscape beside the coming hour's weather, ranked by
how unusual it is, plus hazard warnings) and serves it as a 4-bit PNG whose
palette indices are the panel's seven inks. A Pimoroni Inky Frame 7.3"
(Pico W, MicroPython) fetches it hourly, or within minutes when a warning
appears, and copies it straight to the e-ink. Data comes from the Bureau of
Meteorology, Open-Meteo, NSW RFS and SES. Frame code updates itself over the
air, signed. Everything external sits behind an adapter so the project can
be forked for another place.

## Reading order (about 10 minutes)

1. [behaviours.md](behaviours.md): what the poster does, from the wall. The
   fastest way to learn the vocabulary (hero fact, tiers, map mode, radar
   mode).
2. [architecture.md](architecture.md): the request flow, the alert id, every
   module in one line, the frame's main loop, deploy and tests.
3. [design.md](design.md): why each behaviour is the way it is, with the
   rejected alternatives. Read the relevant section before changing a
   behaviour, and update it when you do.
4. [gotchas.md](gotchas.md): what bit us, grouped by area, each with what to
   do. Skim it before touching the frame, deploying, or adding a source.

## Five things to know before you change anything

- The frame is slow and visible to redraw (~40 s). Anything that changes the
  poster's bytes without changing its meaning costs a redraw.
- Requests are cache-only; only background threads touch the network.
- Business logic sees domain types only; `tests/test_boundaries.py`
  enforces it.
- The real location and hosts live only in gitignored files. Tests, fixtures
  and stills use central Sydney.
- `docs/img` is generated by `server/tests/render_stills.py`; regenerate,
  don't edit. The playground (`docs/playground/`) is hand-written: its
  rules are copied from `render.py` and `facts.py`, so a change to either
  may need the page updated too. Its screenshots in `docs/playground/img/`
  are captures of the page, not renderer output.
